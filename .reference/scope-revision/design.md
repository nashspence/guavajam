# Revised scope and delivery decision — #113

This is the integration recommendation after the maintainer's scope and UI clarification. It supersedes the open scope/delivery choices in the original immutable handoff and its earlier discussion, not its measurements or unrelated source/build/metadata/citation requirements. Riverhog is only a downstream workload. No software-version semantics enter GuavaJam or its static generator.

## Binding logical corpora

| Surface | Searchable corpus | Returned entity |
| --- | --- | --- |
| Collection Works list | Latest accepted edition per work; searchable manuscript/supporting text and current work facts | Work with exact latest-edition evidence |
| Work Versions list, ordinary mode | Every accepted edition's displayed name, declared title, and full commit message; no manuscript/supporting text | Edition |
| Edition Documents | Supporting-document titles and abstracts in exactly the linked edition; generic literal metadata facets | Document |
| Edition Passages | Manuscript and supporting-document passage occurrences in exactly the linked edition, with existing eligible search fields and filters | Passage |
| Work Versions search component, explicit Complete history (passages) mode | Every accepted passage occurrence of that work, not other works | Passage with exact edition/document/anchor/citation |

Resolve latest using verified first-parent publication order, not claimed date. Pin a query to a coherent manifest generation and scope. Collection work metadata/facets and body evidence come from the same latest edition. Keep existing work grouping, deterministic sort/tie rules, and source-exact anchored evidence. The Versions search is not a historical full-text search; do not overload it with body results. Supporting-document metadata filters apply exactly to document occurrences and are inherited by passages. Existing Documents title/abstract full-text semantics remain, rather than silently broadening them to all body or facet text.

Each scope has its own ranking corpus and statistics, not an all-history corpus filtered after ranking. A filter narrows eligible occurrences within the selected scope and does not silently redefine FTS ranking statistics. Compare counts, ordering, evidence and citations against an oracle built from that scope. This is an intentional change from the base worker's all-history search and edition-filtered scores. Complete-history ranking is global within the selected work's passage corpus unless the maintainer explicitly approves changed historical result semantics. Shared bodies must not collapse repeated edition-specific citations. An empty or unpublished work has truthful directory/empty-search behavior, with no synthetic accepted edition or body.

## One clean component on the work's Versions page

Extend the existing optional search component (directory_pages._sqlite_controls(kind='editions', ...), associated search.js/worker). Ordinary Versions mode is the default. Use a single labeled compact selector or equivalent existing-style control for “Versions” and “Complete history (passages)”. Adapt the accessible query label, available sorts/filters, result row presentation and result count to the selected mode; no extra search form, detached call-to-action or section below the editions list. Keep static list, navigation and feeds usable independently of JS. Do not require the exact layout from the offline witness.

Upon choosing history, show a concise notice before execution: “Search passages across all published versions. This may require larger downloads and take longer.” Opening the page, opening the ordinary search disclosure, typing, or selecting history alone must not load history data. Require an explicit history search submission (a nonempty query or deliberately submitted supported filter-only search; a canonical history-query deep link is explicit). History-mode URL without an executed query does not download history. No repeated confirmation within the selected mode. Persist and restore scope/query/filter/sort/page consistently; reset invalid scope-specific controls and page on mode change. Distinguish version rows from edition-specific passage hits. Provide accessible progress, cancellation, retry, and no misleading zero/complete result after failed/incomplete fetch. Cancel superseded work and fence late worker/fetch responses by scope, generation and request ID. Release large resources when no longer needed; no silent background history preload. Test real network abort and memory cleanup, not merely a DOM state change.

## Scoped artifacts first, bounded transport second

Do not build/download a single all-editions work.sqlite just to filter it on the client. Introduce a small versioned generator-owned manifest/catalog routing independent logical artifacts by surface and exact revision or accepted-work-set identity. One collection-wide latest-only document/evidence FTS index; one small Versions title/message index per work; Documents and Passages artifacts per exact accepted edition; one all-history passage-only index per work. A collection does not need the whole work-history passage FTS; it needs full latest-document search plus exact latest-anchored evidence. Documents need no body or passage index. Versions need no document inventory or FTS body. The history index needs no duplicate all-edition document/Versions FTS corpus. Factor edition facts, citation context, and reusable stable ordered source blocks into normalized records while preserving occurrence-level postings for every relevant scope. Reuse the original evidence-window and late-snippet research. Rebuild actual FTS scopes rather than merging shard-local scores or reusing scores from another scope. Store full authoritative source digest/identity, real occurrence-specific citation and exact searchable fields in production; the experiment uses simplified tuples/model metadata.

Build immutable edition artifacts keyed by exact source revision plus relevant renderer/index/schema/tool generation (not mutable latest tip, current count, or later editions). Only mutable pointers/manifests and newly affected derivatives need change when a work advances. Reuse through cache and content-addressing; measure build/hosted bytes as well as downloads, and avoid multiplying rendered HTML or source bodies merely to create scope indexes. Deterministic generation and stale-generation/failure handling remain required. All source validity/retention authority belongs to GuavaJam; search remains optional static generator derivative. Do not introduce runtime server, Riverhog/version-specific fields, inferred applicability, or special product UI.

For ordinary scopes prefer existing simple immutable whole-gzip streaming loader where explicit transfer/memory budgets permit. The name/message and document indexes are particularly good candidates. Scope sizes no longer grow with unrelated history. A large selected edition or many current works can nevertheless exceed an ordinary budget, so do not claim scoping eliminates every resource issue. Use a generic measured transport decision independent of software/version semantics.

For very large all-history (or other legitimately large logical scopes), retain the earlier compressed physical chunk VFS candidate, one global logical SQLite corpus, content-addressed ordinary GET objects, manifest binding schema/generation/order/length/hash, bounded cache/decode/query allocations, and explicit integrity/failure/cancellation contracts. The previous 1/5 edition browser experiments provide feasibility evidence only. The new 50-edition history-only index still exceeds the 256 MiB loader guard, demonstrating why raising that guard or eagerly loading the whole database is not sufficient. Re-evaluate selective/broad/absent queries, scope partitioning, cache policy and evidence windows against a whole-gzip oracle. Do not force VFS complexity onto small scopes. If bounded global history cannot meet agreed budgets, explicitly choose an alternative with the maintainer (e.g. progressive edition-grouped results with relevance local to groups), preserving all matches, exact citations and truthful completeness. No silent score merge, hidden truncation, or removal of history search. Distinguish opt-in latency allowance from permission to exhaust memory. Agree ordinary and history budgets before qualification; history may be slower, not unreliable.

## Implementation sequence and closure criteria

1. Establish explicit scope contracts, source selection, FTS fields and ranking oracles. Implement physical scoped indexes and manifest/worker routing; migrate the search format and cache identity. Implement compact Versions search mode switching in the existing component. Ordinary search must never request history data. The full-text indexes may retain original exact six fields where appropriate, while Versions uses only name/title/message and Documents only title/abstract. Verify edition-only direct links and catalog latest selection, no-edition behavior, historical-only/other-work/message-only/metadata-only sentinels, mixed-field matching, Unicode, empty/missing facets, counts, deterministic ranking/sorts, deep pagination, body evidence, citations, scope transitions and generation identity.
2. Preserve earlier core source/build streaming and guard-removal requirements, generic exact metadata facets (bounded option pages and indexed memberships), normalized occurrence-preserving storage and query/evidence optimizations. Implement reusable source blocks without assuming all anchors form disjoint text. Use original native corpus and final rich GFM; qualify full signed-site validation/render/cache reuse/atomic publication/inventories and malformed or oversized individual resources. No silent skipped content. Keep producer responsibilities in Riverhog and scope out of core publication authority.
3. Qualify ordinary scoped delivery using production installed artifacts and actual browser journeys. Include multiple large current works as well as one large selected edition, latest updates, independent old-edition index reuse, 1/5/50 histories with the same selected edition, small works and no-JS static fallback. Instrument actual network/cache/resource usage; prove no historical passage bytes on ordinary work/edition pages, ordinary Versions query, selecting history without execution. Exercise actual explicit history query/deep link, keyboard/mobile, filters/sort/page restore, rapid scope toggles, cancellation and retries without stale results. Separate WASM, cache, transient and process memory; agree budgets. Preserve original query/evidence correctness against scope-specific oracles.
4. Complete large history qualification using the 50-edition actual native fixture and additional sparse/high-churn/skewed changes, common/rare/absent/mixed-field queries, exact facets, counts, deep pagination and exact historical citations. Browser chunk VFS/whole-gzip comparison, memory/network budgets, Chrome/Firefox/WebKit/mobile, verified hashes, missing/corrupt/truncated/wrong generation, cancellation, interruption, retry and cache eviction remain required. This is a separate decision gate, not automatically a prerequisite for every ordinary-scope optimization. Do not close #113 after only a fast current path. Record explicit disposition of each remaining gate and any approved alternative semantics.
