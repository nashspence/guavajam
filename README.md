## Include selected supporting records

A passage in the manuscript can link directly to the exchange, notebook entry or review that informed it. For example, write `[the endpoint check](supporting/note.json#endpoint)` using the [sample notebook record](templates/work/supporting/note.json). Copy the reviewed record into `works/<slug>/supporting/note.json`. A link to `supporting/note.json` cites the whole record. Ordinary HTTPS links also work for materials preserved elsewhere.

**Either kind of local citation includes the entire selected record in the issued HTML.** The reader lands at the cited passage and can read the surrounding discussion offline. Each record states its scope, gives the source path at the edition commit and displays the SHA-256 of that file. Use the ¶ beside any record or passage to copy its permanent edition URL. The edition fixes the selection at its source commit. A later edition can cite a different selection.

For ChatGPT, keep both the account export and the extracted review copy outside the checkout. Review and redact there before copying a record into the work. The local extraction targets are listed in `make help`. By default the extractor follows the active branch. To capture an alternate reply, use its node ID from the export's `mapping` as the tip. Repeat for other conversations or branches that belong in the edition. Extraction takes user and assistant text from the selected path. It omits alternate replies, messages marked hidden, tool traffic and attachments. An unsupported part in an included message gets a visible placeholder. The edition displays the reviewed text literally, including any Markdown in the original message.

Read every passage before copying the JSON into the work. Keep passage IDs when editing text. In the scope statement, identify excerpts, redactions or other limitations a reader needs to interpret the record. An optional passage `timestamp` may record a source-supported date (`YYYY-MM-DD`) or an offset-qualified instant (`YYYY-MM-DDTHH:MM:SSZ` or a numeric UTC offset); absent timestamps stay absent. The ChatGPT extractor uses each eligible message's available creation time, normalized to UTC, not its later update time. Confirm those timestamps, precision, timezones, and any privacy implications while reviewing the text; do not infer missing dates or treat a notebook transcription date as the original writing date unless supported. Committing a record to this public repository discloses it even when the manuscript never cites it.

## Cite a work across editions

The permanent address for a work as a whole is `https://press.nash.spence.0819870.xyz/works/<slug>`, without a trailing slash. Keep the slug for the life of the work, including after a title change. Use this address to refer to the work across editions. To cite a particular text, choose its numbered edition and use the reading copy or its section permalink.

The work page first appears when the issuer merges a publication receipt. Each subsequent receipt adds an edition with its reviewed title and publication date, ordered by numeric version, highest first. Each entry links to its edition record and displays its current publication, withdrawal or supersession status. The work page identifies an all-withdrawn work and retains every edition citation.

If the issuer later registers a concept DOI, use this permanent work address as its landing URL. First verify the work page and its edition links on the publisher origin and on the recovery host. Record an assigned concept DOI in `registrations/works/<slug>.json`. If the staged proof cites it, commit that assignment by the time you reserve the edition. Regenerate the work page from any receipted edition whenever the assignment changes. To correct or retire a DOI, append one dated entry to `concept_doi_history` with `date`, `from` and `to`, and update `identifiers.concept_doi` in the same change. On retirement, set `to` to `null` and remove the current DOI, keeping an empty `identifiers` object if needed. A later assignment starts with `from` set to `null`. Previously assigned DOIs stay associated with this work. A DOI for an individual edition belongs to that edition and points to its versioned record.

## Issue an edition

Before staging the first work, deploy the publisher-controlled HTTPS origin in `edition-origin.txt`. Each `/works/<slug>/vX.Y.Z` address leads to the edition record. Its `/read` address serves the authorized HTML inline. Keep control of this origin. Enable GitHub immutable releases. Install a GitHub App with only Administration read access on this repository and configure the protected `press-release` environment with its `PRESS_POLICY_APP_CLIENT_ID` variable and `PRESS_POLICY_APP_PRIVATE_KEY` secret. Promotion creates a short-lived token restricted to this repository, checks the live policy before issuing the draft, and revokes the token when the job finishes. Release writes use the built-in workflow token.

The [record gateway](records/worker.js) serves each receipted edition’s checked-in public record and streams the immutable reading copy. Once the claimed edition is public, the record temporarily points to its verified GitHub Release until the receipt and generated page merge. Deploy the current Worker before issuing an edition. Its operator deployment uses `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_ZONE_ID`. Consult `make help` for deployment arguments. The origin must permit noninteractive public reads for reader verification and archive audits. If Cloudflare challenges the verifier, configure a supported exception or change the bot setting; [free Bot Fight Mode has no hostname exceptions](https://developers.cloudflare.com/bots/get-started/bot-fight-mode/).

The primary gateway can also use a private Cloudflare R2 bucket for permanent reading copies. Select an existing bucket in the deployment plan using the arguments in `make help`. Once an edition has a merged receipt, its first uncached GET of `/read` copies the reviewed release HTML to the bucket. R2 verifies the receipt's SHA-256 before committing the bytes. A pending claim continues to use the release. Before announcement, fetch the complete reading copy, check its digest against the receipt and confirm the response header `X-Press-Reading-Source: replica`. A HEAD alone does not populate an empty bucket. Keep the bucket private and retain its objects. The gateway still obtains authorization from the receipt on protected main. Use the independent standby during a wider GitHub outage.

1. Put edition-specific rights and exceptions in `works/<slug>/editions/vX.Y.Z.rights.txt` as one line of plain text. The statement travels with the HTML and appears in the release notes. Put other initial release prose in `works/<slug>/editions/vX.Y.Z.md` as plain-text paragraphs. Provenance preserves the exact reviewed initial release body.
2. Stage a public-safe proof through the [publication workflow](.github/workflows/prepare-edition.yml). Download `verified-edition` and `edition-review`. Read the HTML, rights and complete notes. For a long supporting exchange, navigate to a cited passage and back with a keyboard. Check the size and readability of an illustrated proof on a phone. Independently recompute the authorization from those files using the staging run ID, and compare it with the one supplied. If the proof needs revision, stage the corrected source under the same intended version.
3. To reserve the version, merge the exact reviewed `authorization.json` at `registrations/editions/<slug>/vX.Y.Z.json`. The required check downloads the named run’s proof and verifies the registration before merge permanently reserves that version. If the proof expires before reservation, stage and review a new proof.
4. Before claiming the edition, save all three verified package files outside GitHub Actions and verify that copy against the merged reservation. Once the issuer commits to publication, add `"issuing": true` to the registration and copy the exact reviewed `provenance.json` to `records/editions/<slug>/vX.Y.Z/provenance.json` in a separate PR. Merging the claim commits the version to issuance and freezes its reviewed presentation files. From current `main`, promote the original source SHA, tag, staging run ID and provenance digest. The default proof source is `staging`. If the hosted artifact expires while its run and checks remain available, `rebuild` can reproduce it with the original builder.
5. After GitHub release verification, copy the four files from `edition-receipt` into the checkout at their repository-relative paths. Merge the publication receipt at the registration path, the edition page at `records/editions/<slug>/vX.Y.Z/index.html`, its verified `provenance.json`, and the work page at `records/works/<slug>/index.html` together. If the work has changed in the meantime, regenerate the pages against current `main`. If the artifact is unavailable, regenerate the receipt from the public edition, then generate both pages from the verified package and current checkout. Before announcing the edition, verify the public work page, edition record and reading copy after the receipt merges. If the reader site is down, restore it and retry verification for the same edition.

If the original Actions history is unavailable, use the independently retained proof. In this repository create a temporary draft release with tag `proof-restore-<provenance SHA-256>` and attach the original HTML, `provenance.json` and `SHA256SUMS` under their reviewed filenames. Keep the transport in draft. Promote the original edition with proof source `saved` and the same four inputs. The current issuer commit still needs a successful push validation on protected main. If that evidence has expired, merge a freshly validated change and promote from the new tip. After the real edition and receipt are verified, discard the transport draft. Keep the independent proof copy.

To retire an unclaimed reservation, run [Confirm edition absence](.github/workflows/confirm-abandonment.yml) on main for its original tag. After the protected check succeeds, merge a `cancellation_reason` and its decimal run ID as the string `cancellation_run_id` in the same change. Resolve any new draft or tag before merging. After an issuing claim, repair or retry promotion against the same proof. If publication must stop, merge a public-safe `stop_reason` on the existing claim. The stop is permanent. A promotion already sending its final request may still win. If the release is public, reconcile its receipt and append an editorial notice.

To close an unpublished stopped claim, run [Confirm edition absence](.github/workflows/confirm-abandonment.yml) on main for the original tag. It shares the publication lock and checks for both a tag and a release, including an unpublished draft. If the job finds a draft, inspect it and resolve it before retrying. If the outcome of a publication request remains uncertain, leave the claim stopped until GitHub resolves it. After a successful check, merge its decimal run ID as the string `abandoned_run_id` on the registration. Keep the reviewed provenance and reserve the version permanently. The archive audit reports an unresolved intent until reconciliation or confirmed abandonment.

Keep an independent inventory of issued work and edition paths, including withdrawn editions. For each edition preserve the three package files, receipt, numbered notices, and approved edition page at their repository-relative paths. Retain the editorial checkpoint from approved main separately whenever the receipt, notices or edition page changes. For each work, preserve its generated page and independently retain its SHA-256 digest whenever that page changes. Retain the full approved main commit SHA and its Git objects outside the primary host after each receipt, notice or record-page change. The whole-archive standby check uses that exact commit as its expected inventory and compares every issued edition and work, including withdrawals.

For a repeatable standby export, retain each verified three-file package in a directory named after its complete edition tag beneath a common package root. Export the independently approved commit from a full clone into a new directory outside the checkout. The export includes a Git bundle and the expected commit ID alongside a `public/` directory. Keep the bundle and checkpoint private and separately retain the approved SHA. Deploy only `public/`. Map work and edition addresses internally to their `index.html` and each `/read` to its sibling `read.html`. Preserve direct attachment filenames. Serve the exported bytes without intermediary rewriting; set `Cache-Control: no-transform` on the pages and HTML attachments.

At a recovery host, serve both generated pages at their exact work and edition paths without trailing slashes. Serve the unchanged edition HTML inline at its `/read` path and the three named attachments directly beneath the edition path. After each receipt, notice or page update, use the inventory to verify the affected edition and work page directly on the standby against the independent checkpoints. Before cutover, verify every entry. After cutover set the Actions variable `RECORD_TARGET` to the same base and repeat the checks through the permanent URLs. The GitHub archive audit continues to report loss of the primary release independently.

Keep workflow files compatible between staging and publication. If they drift after a claim, restore compatibility before resuming the same promotion. After issuance, GitHub mirror writes can still fail because of permissions or service availability. The current publisher record is served from the merged page even if the GitHub mirror requires an operator update. [GitHub release API restrictions](https://docs.github.com/en/rest/releases/releases#update-a-release)

Normally start at `v1.0.0`. Bump major for a substantially new edition, minor for a meaningful revision, and patch for corrections.

## Publish an editorial notice

Append the next numbered file at `notices/<slug>/vX.Y.Z/0001.md` and regenerate the edition and work records in the same change. Each file contains one dated line, for example `2026-11-04 Correction: The proof in § 2 cites Theorem 3.` Use `Supersession` or `Withdrawal` for those decisions. To link a replacement edition already issued for this work, end the notice with a suffix such as `[replacement: v1.1.0]`. A supersession points forward. A withdrawal can direct readers to an earlier edition. Use a date on or before today in UTC. Corrections leave the current status in place. If the issuer reverses a withdrawal or supersession, append a dated `Reinstatement` explaining the decision. The edition returns to Published and its record preserves the previous notices.

Confirm with the issuer which work, edition, format, or identity each external identifier names. Add edition identifiers after the receipt is committed. When replacing or retiring an assigned identifier, add the dated correction required by the [history check](scripts/check_editorial_history.py). For an edition DOI, append a dated `version_doi_history` transition with `from` and `to` when changing or retiring the initial assignment, and for later assignments. Remove the current DOI on retirement and omit an empty `identifiers` map. The history entry and numbered correction use the same date. A retired DOI remains associated with its edition.

If a DOI was transcribed against the wrong edition, confirm its owner with the registry. Add `correct_edition` with the intended edition tag to the source transition and record the DOI on that already issued edition in the same PR. The source correction must name the destination. Regenerate the public records for all editions whose identifiers change.

The [editorial synchronization workflow](.github/workflows/sync-editorial-record.yml) checks the public work page, edition record and reading copy after merge, then mirrors the approved notes to GitHub Releases. If it fails, inspect the failure and retry the edition from current main. The [archive audit](.github/workflows/audit-assets.yml) repeats the public checks.
