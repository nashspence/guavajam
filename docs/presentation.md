# Presentation decisions before issuance

Press treats the HTML edition as the publication, not as a page that can acquire
new site-wide styling later. Each edition embeds the exact stylesheet bytes and
records their digest. Once an issuance claim is merged, those presentation files
are frozen; later styles require a successor profile. Current `press.html.v1`
files can still change because no edition has been issued.

## Design basis

The visual language is deliberately scholarly and restrained. [LaTeX.css](https://latex.vercel.app/)
provides useful conventions for mathematical writing; [Simple.css](https://simplecss.org/)
demonstrates readable semantic HTML and dark-mode defaults; and the
[U.S. Web Design System typography guidance](https://designsystem.digital.gov/components/typography/)
provides a defensible prose measure and spacing reference. These are **references,
not imported dependencies**: Press retains its own small stylesheet, system fonts,
no remote styles or font files, no runtime script, and verifiable offline copies.

Reader and record pages intentionally mirror the same `--press-*` palette values.
They are generated by different paths: `styles/edition-v1.css` is embedded by the
versioned edition builder; `PAGE_STYLE` in `scripts/public_record.py` is embedded
by the regenerateable publisher record builder. The offline presentation tests
check that light, dark, and print palette values do not drift between them.

The publisher keeps native tables, MathML and preformatted code. Table and
display-math blocks have one focusable scrolling `div`; native `pre` elements
receive focus directly, including when Pandoc adds a syntax-highlighting wrapper.
These focus targets are named `group` elements, not landmarks. Their context names
are “Table”, “Displayed mathematics” and “Code block”. A native table's accessible
name still comes from its own caption; the wrapper does not repeat that caption
or assign another name to the table.

This choice follows an Orca 46.1 / Firefox 157 trial: generic focusable wrappers
were silent on focus, while named groups supplied context without adding regions
to landmark navigation. Naming the group from the caption repeated the caption
when entering the native table, so the group keeps only its context name. Orca's
native table navigation continued to report captions, headers, cell values and
row/column positions. These observations do not establish identical speech in
VoiceOver or NVDA; retain those combinations in future manual release reviews.

All three targets keep an explicit tab stop and visible focus. WebKit's tested
keyboard sequence skipped overflowing code without one, although Chromium and
Firefox reached it automatically. Pinned Pandoc puts highlighted CodeBlock AST
attributes on the outer syntax-highlighting `div`; the shared publisher HTML
pass therefore adds focus to the native `pre` after rendering. It preserves all
code markup and text. Even a short sample can overflow after text zoom, a font
change or a narrower viewport; static HTML cannot conditionally focus only the
currently overflowing samples. The small cost of a tab stop on a fitting sample
is deliberate. No script, extra code container or new source annotation is used.

Tables use automatic width constrained by the viewport and ordinary cell text
wraps at word boundaries. Simple and text-heavy tables fit phone widths; native
math and unbroken identifiers retain their intrinsic minimum widths and pan
inside the wrapper when necessary. Numeric columns are not forced to break into
individual characters. Captions remain native table children. Print retains the
full-width table and paper-specific wrapping rules. Supporting-record passages
remain escaped, literal text owned by the edition CSS.

English public-record pages keep `lang="en"` on their publisher chrome. Visible
authored titles in headings, citations, work-detail values and edition links get
a local language span from each edition's reviewed language when it differs from
English. A mixed-language work does not lend one edition's language to another.
Language values use the same validated source grammar and title text is escaped;
older verified provenance without a language field keeps its existing unmarked
output rather than acquiring an invented language declaration.

Pandoc emits each footnote citation as an anchor containing a superscript numeral.
The underline must belong to that raised numeral, not its enclosing anchor:
otherwise the underline sits at the paragraph baseline far below the number.
Footnote backlinks remain visibly colored and keyboard-focusable, with a less
intrusive arrow treatment. Inline code gets a subtle paper-toned backing while
preformatted blocks retain scrolling and their distinct presentation.
The checked-in `docs/reader-preview.html` deliberately mirrors the actual
Pandoc footnote structure and embeds the *exact* current edition CSS; the
presentation tests reject drift between the two.

## Mathematical hierarchy and tables

Before the first issuance, four treatments were compared side by side at 375px
and 1120px in light and dark Chromium: the initial boxed table and larger
formal headings; compact headings with horizontal-rule tables; the same with
automatically italicized theorem prose; and a partially compact alternative.
The compact, non-italicizing treatment kept a clearer hierarchy between
section headings and mathematical assertions, without sacrificing heading IDs
or the 44px minimum permalink target. Horizontal rules were easier to follow
than a full grid, especially on narrow screens where columns scroll. Captions
are visually secondary and must supply any actual numbering in the source,
not through generated CSS counters.

The compiler keeps the existing GFM reader and normalizes the narrow
[caption directive](table-captions.md) into a native table caption before
accessible scroll wrapping. The starter exercises this actual compile/build
path. A prose label without the directive remains ordinary prose; caption
wording and numbering always belong to the author.

This is an intentional *partial* adoption of LaTeX conventions. Press keeps
formal statements as explicit source headings, so an adjacent paragraph might
be introductory material rather than the entire theorem. Blanket automatic
italics, generated theorem numbers, and invented end-of-proof markers could
misstate source structure; the author owns those distinctions. Print tables
retain the light/dark-independent rule treatment, with editorial review still
needed when exceptionally wide material will not fit the paper.

## Supporting records: documentary evidence, not a chat application

Supporting records deliberately share the main edition's paper/ink palette and
serif text, but have their own quieter hierarchy. Tufte CSS's academic restraint,
Primer's compact chronological reading rhythm, and GOV.UK Summary List's clear
metadata labeling inform the layout; no library is imported. The record title
and scope introduce the material. A small semantic definition list keeps the
**complete** source path and SHA-256 digest visible, selectable, and printable,
while passage headings use smaller system text and thin rules. The first entry
follows the provenance without a redundant second rule. There are no chat
bubbles, participant avatars, or styling inferred from a speaker label.

The reviewed JSON record format still requires `title`, `scope` and `passages`.
Each passage retains `id`, `label` and literal `text`, with an **optional**
`timestamp` string. A date-only value `YYYY-MM-DD` remains date-only; a datetime
must specify seconds and an explicit timezone (`Z` or `+HH:MM`/`-HH:MM`). Invalid
calendar dates, unsupported values and missing zones fail validation. The visible
short date/time is always paired with a semantic `<time datetime="...">` holding
the exact reviewed value; no client clock or script interprets it. Do not
manufacture precision or infer a timestamp from record order, file modification,
extraction time, or author identity.

The ChatGPT import copies an eligible message's numeric `create_time` in UTC,
retaining available fractional seconds; it never uses `update_time` to fill in
missing creation times. Timestamps can disclose private chronology, so review
and redact them in the private extraction copy **before** committing. Notebook
dates must be supported by their own source; partial dates must not be upgraded
to fabricated times. A record without any timestamps remains valid.

The supporting-passage renderer escapes the original text and preserves line
breaks and Markdown characters literally. Its stable IDs, complete provenance,
standalone HTML, and versioned CSS remain unchanged in purpose. The separate
[illustrative supporting-record preview](supporting-record-preview.html) is
not an issued edition; its dummy notebook and conversation timestamps exist
only to exercise the visual treatment.

## Release review

Review the HTML generated from the **starter manuscript**, including a wide table,
long equation, linked footnote superscript and backlink, proof, inline and
fenced code, image, notebook entry and long chat with and without timestamps,
long SHA-256 and source paths, and a long permanent URL. Check phones (320px and 375px), tablet, desktop, light/dark system
preferences, keyboard focus and horizontal panning, browser text zoom/reflow, and
print output while the OS prefers dark mode. Long equations and wide tables can
require editorial attention on paper even when they scroll successfully on a phone.
Run the repository's pinned test and source validation checks before accepting a
presentation change; the edition builder requires the specified Pandoc release.

No archival fixture or previously issued artifact should be re-styled in place.
In particular, `tests/fixtures/archived-v1` remains an independent old-profile
verification fixture, not a template for new editions. The independent record
projection and the immutable reading-copy digest checks must continue to pass.
